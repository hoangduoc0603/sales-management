# Catalog Product & Variant Completion Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Hoàn thiện cụm Hàng hóa và biến thể để quản lý Product, Variant, SKU, barcode, đơn vị bán và trạng thái kinh doanh theo design Open Design đã duyệt.

**Architecture:** Giữ `Variant` là đơn vị giao dịch duy nhất. Frontend Catalog gọi API qua `ApiClient`; backend Apps Script xử lý qua `CatalogService` và `CatalogRepository`, không truy cập Sheets từ UI. Các mutation lưu dữ liệu ở record nguồn, không tạo audit riêng.

**Tech Stack:** React + TypeScript + Vite frontend, Apps Script service/repository backend, shared contracts/schemas, Vitest.

## Global Constraints

- Source of truth nghiệp vụ: SRS → ADR Accepted → Solution/System Design → LLD/data dictionary → code hiện có.
- UI phải follow `catalog-crm-commercial.html` và `catalog-product-editor-policy-builder.html`, Design System Cenio Core v0.7, không dùng native select cho UI chính.
- Product không là đơn vị giao dịch; mọi sale/purchase/inventory/pricing/barcode tham chiếu `variantId`.
- Không hard delete product/variant đã có khả năng tham chiếu; dùng deactivate/reactivate.
- Không ghi AuditOutbox/AuditLog; dùng actor metadata trên record khi model hỗ trợ.
- Performance-first: query danh mục phải đọc cache/projection, mutation chỉ ghi các bảng cần thiết và invalidate cache liên quan.
